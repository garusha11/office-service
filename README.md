# Office Ops

Учебная админ-панель службы эксплуатации офиса на Java и Spring Boot. В системе ведут реестр оборудования и обрабатывают заявки на ремонт: диспетчер назначает исполнителя, техник выполняет работу, диспетчер закрывает результат. Администратор настраивает права ролей и учётные записи. Все существенные действия попадают в журнал.

## Возможности

- Вход по логину и паролю; пароли хранятся как BCrypt-хеши.
- Реестр оборудования с инвентарным номером и расположением.
- Создание заявок и последовательный переход `Новая → Назначена → В работе → Решена → Закрыта`.
- Назначение активного исполнителя, которому разрешена работа по заявкам. Только назначенный исполнитель может начать и завершить работу.
- Управление операторами, блокировка учётных записей и настройка разрешений ролей через браузер.
- Проверка прав на сервере при каждом запросе. Изменение разрешений действует для уже вошедшего пользователя.
- Журнал последних 100 действий и защита форм от CSRF.

## Технологии

Java 17+, Spring Boot 3.5.16, Spring MVC, Spring Security, Spring Data JPA, Thymeleaf, H2, Maven.

## Запуск

Нужны JDK 17+ и Maven 3.6.3+. Из каталога проекта:

```powershell
$env:OFFICE_ADMIN_PASSWORD = 'ReplaceWithAStrongPassword123!'
mvn spring-boot:run
```

Откройте <http://localhost:8080>. Логин: `admin`, пароль: значение `OFFICE_ADMIN_PASSWORD`. При первом запуске пароль должен быть длиной не менее 12 символов. При повторном запуске пароль не меняется: учётная запись уже находится в БД.

Данные находятся в `data/` и не попадают в Git. Для нового демонстрационного запуска остановите приложение и удалите папку `data`. Не используйте реальные рабочие пароли в учебном проекте.

Проверка и сборка:

```powershell
mvn test
mvn package
```

## Роли и права

| Роль | Начальные права |
| --- | --- |
| `ADMIN` | Все права, включая настройку доступа и журнал |
| `DISPATCHER` | Просмотр оборудования, просмотр и создание заявок, назначение исполнителя, закрытие заявки |
| `TECHNICIAN` | Просмотр оборудования и заявок, работа по назначенной заявке |
| `AUDITOR` | Просмотр оборудования и заявок, просмотр журнала |

Права `DISPATCHER`, `TECHNICIAN` и `AUDITOR` можно изменять на странице **Доступ**. `ACCESS_MANAGE` нельзя выдать другим ролям. Роль `ADMIN` защищена: нельзя изменить её права, создать второго администратора, отключить или переназначить основного. Это сохраняет способ исправить ошибочную настройку разрешений.

Права: `ASSET_READ`, `ASSET_WRITE`, `TICKET_READ`, `TICKET_CREATE`, `TICKET_ASSIGN`, `TICKET_PROGRESS`, `TICKET_CLOSE`, `ACCESS_MANAGE`, `AUDIT_READ`.

## Архитектура

```text
Браузер → Spring Security → PagesController → AdminService / TicketService → Repository → H2
                      │                              │
                      └──────── AccessGuard ◀────────┘
                                                    │
                                         TicketCommand implementations
```

`PagesController` принимает запросы и готовит данные для Thymeleaf. Сервисы выполняют бизнес-правила и записывают журнал. `AccessGuard` проверяет разрешения по текущей роли из базы. Репозитории отвечают за сохранение данных. Переходы заявок оформлены отдельными командами (`StartWork`, `ResolveTicket`, `CloseTicket`), которые определяют допустимость, требуемое право и изменение статуса.

### SOLID

- **Single Responsibility**: контроллер отвечает за HTTP, `TicketService` — за работу с заявками, `AccessGuard` — за права, `AuditRepository` — за хранение событий.
- **Open/Closed**: новый переход заявки добавляется реализацией `TicketCommand`, без изменения логики выбора команды в `TicketService`.
- **Liskov Substitution**: любую реализацию `TicketCommand` можно вызвать через общий контракт `supports/execute`.
- **Interface Segregation**: контракт `TicketCommand` содержит только операции, нужные обработке перехода.
- **Dependency Inversion**: `TicketService` получает список реализаций интерфейса `TicketCommand` через конструктор; зависимости предоставляет Spring.

### Паттерны

- **Command**: отдельные классы для начала, завершения и закрытия работы.
- **Repository**: Spring Data интерфейсы отделяют бизнес-логику от JPA.
- **MVC**: контроллеры, модель и Thymeleaf-шаблоны.
- **Dependency Injection**: внедрение зависимостей через конструкторы.

## Сценарий демонстрации

1. Войти под `admin`, добавить объект оборудования.
2. Создать оператора с ролью `TECHNICIAN` и заявку на этот объект.
3. Назначить техника, войти под его учётной записью и перевести заявку в состояния **В работе** и **Решена**.
4. Под администратором закрыть заявку и открыть журнал действий.
5. У роли `AUDITOR` убрать `ASSET_READ`, открыть страницу оборудования в уже активной сессии аудитора и показать отказ в доступе.
6. Показать `TicketCommand`, `TicketService`, `AccessGuard` и объяснить применение SOLID.

## Границы учебного проекта

Для простого локального запуска используются H2 и автоматическое обновление схемы. Для эксплуатации в организации потребуются миграции базы, резервное копирование, постраничный журнал, мониторинг и дополнительные меры защиты. Журнал здесь демонстрационный: администратор базы может изменить его записи.
